1. **[已解决] 后端当前无法正常导入应用**

   - `backend/app/main.py:1041` 使用了 `ItineraryRevisionOut`，但 `backend/app/main.py:24` 的 schema 导入列表没有导入该名称。
   - 执行 `backend/.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider` 时，测试收集阶段因 `NameError: name 'ItineraryRevisionOut' is not defined` 失败。
   - 影响：后端测试无法运行，应用启动和 OpenAPI 路由加载也存在阻断风险。
   - 建议：补齐导入后重新执行后端测试，并检查所有路由的启动导入依赖。
   - 解决日期：2026-09-01。
   - 解决证据：当前后端应用可以导入，`/api/v1/health/ready` 返回 `ready`；测试能够完成收集并执行 20 个用例，当前结果为 `19 passed, 1 failed`，剩余失败与排行测试数据隔离有关，不再是 schema 名称导入错误。

2. **[未解决] REST API 清单与实际路由不一致**

   - 开发文档 `11.2`、`11.5`、`11.7` 声明了邮箱验证、密码找回、城市和景点后台 CRUD、导入、排行任务、审计等接口，但当前 `backend/app/main.py` 没有对应实现。

   - 文档 `11.1` 要求所有列表分页并返回 `items/total/page/page_size`，当前城市、景点、排行、会话和行程列表返回数组，没有统一分页结构。
   - 文档声明统一返回 `error.code/message/request_id`，当前代码主要使用 FastAPI 默认的 `detail` 错误结构。
   - 建议：以实际 OpenAPI 为基准补齐接口，或把未实现接口明确标为规划项，并统一路径、方法、状态码、分页和错误结构。

3. **[未解决] 前端页面路径与文档不一致且部分页面没有路由**

   - 建议：补齐页面后再写入已实现清单，或将页面状态区分为“已实现”和“规划中”。

4. **[未解决] 数据模型章节与当前 SQLAlchemy 模型差异很大**

   - 文档描述了 `auth_action_tokens`、`ranking_snapshots`、`user_behavior_events`、`ranking_daily_metrics`、`travel_requests`、`city_access_estimates` 和 `itinerary_revision_groups` 等结构，当前 `backend/app/models.py` 没有对应模型。

   - 建议：明确数据模型章节是目标设计还是当前数据库结构；如果作为开发契约，应补充正式迁移和模型实现，否则应标注未实现字段。

   - 影响：文档中的“约束校验”“季度热门排行”和相关验收标准会高估当前功能。
   - 建议：将未完成部分标为“未启用/P1”，并在实现后补充真实数据来源、算法版本和测试证据。

7. **[未解决] Worker、数据库迁移和部署描述与当前工程状态不一致**

   - 建议：在文档中明确本地开发兼容模式与生产模式，生产部署前完成 Alembic 初始迁移、升级和恢复演练。

8. **[未解决] 文档版本和项目状态表达不完整**

   - 文档顶部标记版本 `V1.3`，但 `21. 修订记录` 最后只有 `V1.2`，没有对应的 V1.3 条目。

   - 建议：补充 V1.3 修订记录，并增加“目标规范/当前实现/剩余工作”状态表，避免把设计目标误读为已完成能力。

### 发现的问题

1. **[未解决][高] 自动化测试直接污染开发数据库**

   - 事实依据：`backend/app/core/config.py:8` 默认数据库为 `sqlite:///../travel.db`；`backend/tests/conftest.py:6-8` 只关闭外部 LLM，没有为测试覆盖数据库；`backend/tests/test_user_features.py:33-91` 会注册随机用户、写入资料、收藏、最近浏览、行程、版本、反馈和分享链接，测试结束后没有清理。
   - 验证证据：本次执行后端测试得到 `19 passed, 1 failed`；失败用例 `test_global_attraction_ranking_returns_top_ten_from_all_cities` 期望全部为初始化分数，但实际数据库已有 `weighted_behavior` 行为分数。
   - 影响：每次运行测试都会增加开发用户和业务数据，测试结果受历史数据影响，无法稳定复现，也可能误伤真实开发数据。
   - 建议：在导入应用前强制配置临时 SQLite 测试库或事务回滚夹具；每个用例隔离数据；测试默认拒绝连接开发和生产数据库。现有测试数据只能在确认范围后清理。

2. **[未解决][高] 注销账号没有撤销公开分享链接**

   - 事实依据：`backend/app/main.py:559-579` 只撤销 `AuthSession`、停用账号并释放 `public_id`，没有更新 `ShareLink.revoked_at`；`backend/app/main.py:1188-1194` 的匿名分享读取只检查 Token、撤销时间和过期时间，不检查行程所属账号状态。
   - 影响：用户注销后，原分享链接在有效期内仍可能继续公开访问保留的私人行程，与开发文档 `5.1.4` 和注销验收要求冲突。
   - 建议：在同一事务中撤销该用户全部行程的分享链接，并增加“创建分享后注销账号，原链接返回 404”的自动化测试。

3. **[未解决][高] 首次启动仍创建可预测的管理员凭据且认证缺少限流**

   - 事实依据：`backend/app/main.py:120-121` 在没有管理员时自动创建用户名 `admin`、密码 `123456` 的账号；`backend/app/main.py:368-408` 的登录和注册接口没有账号/IP 限流；配置类也没有认证限流参数。
   - 影响：隐藏登录页面上的演示文字并不能消除固定密码风险；新环境如果直接暴露服务，管理员账号可以被猜中，登录接口也容易遭受暴力尝试。
   - 建议：改为一次性部署命令或环境注入创建管理员，禁止使用固定默认密码；为登录、注册、找回和验证动作增加账号/IP 双维度限流和审计。

4. **[未解决][高] 行程删除不符合软删除和关联数据保留规则**

   - 事实依据：`backend/app/main.py:1014-1024` 直接执行 `db.delete(itinerary)`；`ItineraryRevision`、`ShareLink` 和 `ItineraryFeedback` 只有外键，没有 ORM 级联关系；`backend/app/db.py:13-15` 没有显式启用 SQLite 外键约束。
   - 影响：可能遗留找不到所属行程的修订、分享和反馈记录；删除后无法按后台保留策略恢复，也没有同步撤销分享或停止任务，与开发文档 `11.5` 的逻辑行程组删除规则冲突。
   - 建议：增加行程软删除字段和状态过滤；删除事务中撤销分享、停止活动任务并保留审计；为所有关联表明确数据库外键策略和 ORM 关系。

5. **[未解决][高] 城市列表包含后端不支持的模拟城市和虚构统计**

   - 事实依据：`frontend/src/views/CityList.vue:8-126` 写死北京、上海、成都、东京、京都、首尔、巴黎、里斯本和新加坡，并写死景点数量及外部图片；`CityDetailPage.vue:24-26` 只在后端返回城市中按 slug 查找；当前后端种子只有北京、上海和成都。
   - 影响：用户点击东京、巴黎等卡片会进入“城市不存在”；页面展示的景点数量和图片也不来自当前资料库，容易误导用户。
   - 建议：城市列表统一读取 `/api/v1/cities` 和实际景点数量；未支持城市不得提供可点击详情入口，预览城市需要明确状态并使用已核验素材。

6. **[未解决][高] 管理后台城市、景点、导入、排行和审计没有完整实现**

   - 事实依据：`AdminCitiesPage.vue` 和 `AdminAttractionsPage.vue` 只调用公开读取接口进行搜索、筛选和展示；后端没有 `/api/v1/admin/cities`、`/api/v1/admin/attractions`、`/api/v1/admin/imports`、`/api/v1/admin/rankings` 或 `/api/v1/admin/audit-logs` 写接口。
   - 影响：管理员不能新增、编辑、停用、删除、批量导入或审核城市、景点、图片和排行，也无法查看操作审计；README 对后台 CRUD、导入和审计的描述高于实际能力。
   - 建议：按城市、景点、媒体、导入、排行和审计拆分后台接口；所有写操作校验管理员、CSRF、并发版本并写入不可删除的审计日志。

7. **[未解决][中] 账号安全功能没有形成邮件验证闭环**

   - 事实依据：当前只有密码保护下的直接邮箱更新；没有邮箱验证、重发验证邮件、找回密码、重置密码和密码修改安全通知路由。`SecuritySettingsPage.vue:14` 也明确提示邮件服务尚待配置。
   - 影响：无法确认注册邮箱和新邮箱归属；用户忘记密码后无法自助恢复；密码被修改时没有站外安全提醒。
   - 建议：增加一次性哈希令牌、过期和单次使用规则，接入事务邮件适配器，并覆盖账号防枚举、重复使用和超时测试。

8. **[未解决][中] 分享管理和评论区只有单向提交能力**

   - 事实依据：后端有创建和单条撤销分享接口，但没有查询当前行程分享记录的接口；`frontend/src/api.ts:110` 和 `ItineraryDetailPage.vue:20` 只创建、复制链接，没有历史列表和撤销入口。反馈查询 `backend/app/main.py:1151-1156` 只返回本人的评分、评论及聚合分数，不返回评论列表。
   - 影响：刷新页面后用户无法找到曾创建的链接进行撤销；所谓评论区实际上只是本人反馈表单，其他评论不可见，也没有删除、举报或分页。
   - 建议：增加分享列表、复制、有效期、撤销状态；明确评论是私人反馈还是公开评论。如果公开，需要评论列表、分页、删除、举报和审核策略。

9. **[未解决][中] 实时排行算法和数据采集只完成初级版本**

   - 事实依据：`backend/app/main.py:679-698` 使用资料完整度、标签、票价、时长以及收藏、最近浏览和对话名称包含次数计算请求时分数；没有搜索点击事件、加入行程事件、评分权重、时间衰减、周期聚合、季度快照和趋势表。
   - 影响：当前分数不是开发文档定义的季度热度排行，重复浏览和自动化测试数据也会改变结果；无法解释历史趋势或复现某季度榜单。
   - 建议：先建立去重行为事件和每日聚合，再按固定算法版本生成季度快照；外部热点只能作为标明来源的输入，不能让大模型直接修改最终分数。

10. **[未解决][中] AI 自然语言重规划没有接入结构化 LLM 操作**

    - 事实依据：`backend/app/main.py:1105-1148` 明确使用正则表达式本地解析天数、预算、删除和替换景点；`backend/app/llm.py` 当前只用于普通对话和行程交付摘要。
    - 影响：复杂表达、同时调整多个条件、顺序修改、每日时间和偏好变更可能无法识别；页面提示“自然语言调整”容易让用户误以为支持开放式重规划。
    - 建议：让 LLM 只输出白名单结构化修改操作，服务端逐项校验城市、景点、时间、预算和版本后执行；无法解析时返回明确澄清问题。

11. **[未解决][中] 地图路线、真实图片和完整预算仍未实现**

    - 建议：先接入地图路线缓存和失败降级，再扩展预算分项；图片必须按城市、景点、用途、来源、授权和审核状态管理，未核验素材不得展示。

12. **[未解决][中] 反馈后台只能查看，不能处理**
