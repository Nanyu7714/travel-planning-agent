# 媒体资源管理

## 目标

城市和景点图片统一登记在 `media_assets` 表中。图片可以来自远程 URL、本地文件或对象存储，但必须明确归属城市、内容、用途、来源和核验状态。

## 分类规则

```text
城市封面：<city-slug>:city:cover
景点封面：<city-slug>:attraction:<attraction-id>:cover
```

每条记录保存：

- `city_id`、`attraction_id` 和 `purpose`：图片属于哪个城市、景点及用途。
- `storage_type`：`remote_url`、`local_file` 或 `object_storage`。
- `url` 和 `storage_path`：浏览器地址及本地/对象存储路径。
- `alt_text`：图片替代文本。
- `source_name`、`source_author`、`license_name`、`attribution_url`：来源和授权信息。
- `verification_status` 和 `is_active`：核验状态及是否允许展示。

## 核验状态

```text
approved             内容和来源已核验，可以展示
needs_review         等待人工核验
missing              已创建分类槽位，但尚无图片
rejected_wrong_city  图片内容与所属城市不符，禁止展示
```

前端只使用 `is_active=true` 的图片。空地址、禁用图片或加载失败时显示统一占位状态，不回退到其他城市或无关景点图片。

## 本地文件

本地图片放入 `backend/media/`，按 `cities/<slug>/cover/` 或 `attractions/<slug>/<id>/cover/` 分类。后端通过 `/media/` 提供静态访问。

## 远程图片

远程图片直接保存 URL，但不能只保存图片地址。使用 Wikimedia Commons、Unsplash、景点官网或文旅部门资源前，必须核对单张图片的作者、许可证和原始页面。

禁止使用随机图片接口、搜索结果缩略图、来源不明的旅游网站图片，或用城市封面冒充景点图片。

## 自动候选图

管理员在“图片管理”中对未启用的图片记录点击“自动找图”后，后端会使用景点名、城市名和 `China` 组成检索词，调用 Wikimedia Commons 的 MediaWiki API 搜索文件命名空间。系统只保存第一张带原始页面地址的候选图，并登记可取得的作者和许可证字段。

自动搜索的结果固定为：

```text
verification_status = needs_review
is_active = false
```

这一步只是“找到候选”，不代表图片正确或可以使用。管理员必须在后台预览图片、打开原始页面核对景点内容、作者和许可证，再将状态改为 `approved` 并启用。找不到结果、接口超时或来源信息不足时，系统不会写入假图片，管理员可手动填写已核验的图片资料。

## 后台管理

管理员通过“管理后台 → 图片管理”可以：

- 按城市、核验状态和关键词筛选全部媒体记录。
- 为未启用的城市或景点图片自动查询候选图。
- 编辑图片地址、本地文件相对路径、替代文字、来源、作者、许可证和原始页面。
- 将核验状态设为 `approved` 后启用前台展示；未核验图片不能启用。

已启用图片不会被自动搜索覆盖，替换时应在编辑面板中手动填写并核验新的图片资料，避免前台在审核期间失去原图。
