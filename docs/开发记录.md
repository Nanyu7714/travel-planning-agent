# 旅游规划 Agent 开发记录

本文档是项目的任务开发日志。每次完成任务后，记录完成内容、实现位置、验证结果和遗留问题。

## 当前项目状态

项目已经完成一个可以本地运行的 MVP（最小可用版本）：用户可以注册或登录，进入 AI 规划页面进行多轮旅行咨询，查看会话历史，清空当前对话，并生成北京、上海、成都的示例行程。管理员可以查看平台概览。

当前版本使用规则和固定数据驱动景点选择及约束校验，并已支持配置兼容 OpenAI Chat Completions 的大模型完成普通对话和行程说明。本机尚未配置真实模型服务和实时景点接口。生产环境还需要按开发文档迁移到 PostgreSQL，并继续完善后台管理、行程版本、分享链接等功能。

## 技术栈和目录

- 前端：Vue 3、TypeScript、Vite、Element Plus、ECharts、Lucide 图标。
- 后端：FastAPI、Pydantic、SQLAlchemy、Alembic、Uvicorn。
- 数据库：本地 SQLite；生产目标为 PostgreSQL。
- 交互：REST API 提交消息，SSE（服务端推送事件）反馈规划进度。
- 主要目录：`frontend/` 前端、`backend/` 后端、`backend/tests/` 后端测试、`docs/` 项目记录。

### 2026-09-01：实现浏览器登录状态自动续期

完成内容：

- 新增 `auth_sessions` 表，只保存 Refresh Token 和 CSRF Token 的哈希、Token 家族、设备名称、有效期、最近使用时间及撤销状态，不保存明文 Token。
- 登录和注册后同时签发 15 分钟 Access Token 与 7 天 Refresh Token；两个 Token 均使用 `HttpOnly` Cookie，CSRF Token 单独绑定到认证会话。
- 新增 `POST /api/v1/auth/refresh`。刷新时校验 Refresh Token、CSRF Token、会话有效期和账号状态，并轮换 Refresh Token、CSRF Token 和 Access Token。
- 退出登录时撤销当前认证会话并清除访问、刷新和 CSRF Cookie，已撤销的 Refresh Token 不能再次使用。
- 前端 API 层遇到 `401` 后使用单一并发刷新请求获取新令牌，并自动重试原请求；刷新失败或超过 7 天时才打开登录窗口。
- 测试环境强制关闭真实大模型调用，避免自动化测试消耗外部模型额度。

验证结果：

- 后端执行 `.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider`，结果为 `13 passed`。
- 前端执行 `vue-tsc -p tsconfig.app.json --noEmit --incremental false`，类型检查通过。
- 前端执行 `npm.cmd run build`，Vite 成功转换 `1591` 个模块并生成生产构建。
- 真实 HTTP Cookie 验证中，移除 Access Token 后 `/auth/me` 返回 `401`，调用 `/auth/refresh` 返回 `200`，随后 `/auth/me` 恢复为已登录用户，并获得轮换后的 Refresh Token。
